## 경계 판정 (먼저 검토할 칸)

- **이서윤 P-01** (●): 인터페이스 대상 시스템과 송수신 데이터를 정의하고 API 명세서와 오류 코드 체계를 작성했다. → 오류 코드 체계를 '오류 시 처리 방안'으로 보았다. 처리 방안(재시도 등)이 따로 없다고 보면 부분 충족이다.
- **박지훈 P-03** (●): 대외기관 연동 요구사항을 분석해 인터페이스 요구사항 검증표를 만들고 누락 오류 코드를 개발 전에 찾았다. → '개발 범위를 정했다'는 말은 없다. 요구사항 검증표 작성을 범위 확정으로 보았다. 엄격히 보면 부분 충족이다.
- **최하은 Q-05** (●): 모든 PR이 JUnit 테스트를 거친다. 기술 스택에 JUnit이 있다. → 팀 규칙 문장이라 본인이 테스트를 썼는지는 직접 드러나지 않는다. 확인 필요로 볼 여지가 있다.
- **최하은 P-01** (●): 택배사 12곳 연동 인터페이스를 설계해 설계서를 썼고 장애 시 재처리 큐로 예외를 처리했다. → 오류 처리를 설계서에 명세했다는 말은 없고 구현만 있다. 엄격히 보면 부분 충족이다.
- **한지원 P-02** (◐): 공통 연동 모듈을 구현하고 암호화 · 접근 권한 검증(보안)을 적용했지만 실패 시 예외 처리 구현은 드러나지 않는다. → 오류 처리 방안을 명세했다(P-01)는 문장을 구현으로 보면 충족이다.
- **정민준 P-02** (◐): 암호화 · 접근 토큰 검증(보안)은 적용했지만 실패 시 예외 처리 구현은 드러나지 않는다 (재전송 규칙은 명세). → 재전송 규칙을 명세했다는 문장을 예외 처리 구현으로 보면 충족이다.
- **오세진 P-05** (●): 엔티티 클래스와 ERD를 설계했다. → ERD를 '다이어그램 결과물'로 보았다. 상세 설계서가 따로 없다고 보면 부분 충족이다.
- **윤채린 Q-04** (●): 협업하며 코드 리뷰를 한다. GitHub Actions를 쓰는 팀이다. → Git이라는 말이 직접 없다(기술 스택의 GitHub Actions뿐). 엄격히 보면 확인 필요다.
- **임수아 P-03** (◐): 요구사항 회의에 참여해 기능 범위를 정리했다. 범위를 본인이 정했는지는 드러나지 않는다. → '기능 범위를 정리했다'를 범위 결정으로 보면 충족이다.
- **조은우 P-04** (◐): Jenkins 빌드 · 배포를 운영하고 배포 후 확인 · 복원을 했지만 파이프라인을 본인이 구성했는지는 드러나지 않는다. → '운영했다'를 구성으로 보면 충족, 이미 있는 파이프라인을 쓴 것으로 보면 미충족이다.
- **전하린 P-05** (●): 스키마를 설계하고 기능 목록으로 클래스 다이어그램을 그렸다. → 다이어그램을 '그렸다'뿐이라 상세 설계인지 불분명하다. 엄격히 보면 부분 충족이다.
- **송주원 P-03** (○): 개발 전에 현행 시스템 구성을 파악했을 뿐 요구사항을 분석해 범위를 정한 기록은 없다. → '현행 시스템 파악'을 분석 참여로 보면 부분 충족이다.
- **양시우 P-01** (●): 협력사 연동 인터페이스를 설계해 설계서를 썼고 송수신 데이터와 연동 방식을 명세했으며 예외 처리를 구현했다. → 오류 처리 방안을 명세했다는 말은 없고 예외 처리 구현만 있다. 엄격히 보면 부분 충족이다.
- **이도윤 Q-02** (●): 개인 프로젝트에서 Spring Boot로 결제 승인 · 취소 API를 만들었다. → 실무가 아닌 개인 프로젝트다. 'REST API'라는 말은 없지만 API 개발로 보았다. 실무만 세면 미충족이다.
- **이도윤 Q-03** (●): MySQL로 결제 테이블을 혼자 설계하고 구현했다. → SQL 작성이 문장에 직접 없다. 테이블 설계만으로 보면 부분 충족이다.
- **이도윤 Q-04** (○): Git 협업이나 코드 리뷰 기록이 없다 (오픈소스 문서 수정만 있다). → 오픈소스 기여를 Git 협업으로 보면 부분 충족이다.
- **최지우 Q-02** (●): Spring Boot를 독학하며 게시판 API를 만들었다. → 실무가 아닌 독학 결과물이다. 이도윤 개인 프로젝트와 같은 기준으로 충족으로 보았다. 실무만 세면 미충족이다.
- **최지우 Q-04** (○): Git 협업 기록이 없다 (로그 분석과 코드 리뷰를 반복했다는 말만 있다). → Git 없이 코드 리뷰만 나온다. 리뷰를 협업 근거로 보면 부분 충족 이상이다.
