# 지원자 검색 개선 비교

## 범위

기존 더미 지원서 텍스트를 사용했다. PDF 추출과 OCR은 평가하지 않았다. 결과는 가상 지원자 자료와 지정된 질문에 대한 측정이며 실제 지원자 전체의 성능을 보장하지 않는다.

## 정답이 정리된 가상 지원자 8명

중간 구현을 기준으로 `tests/samples/README.md`의 금융 도메인 실무 경험 정답인 정유민, 김하늘, 한예린을 확인했다. 로컬 BGE-M3와 설정된 실제 모델을 사용해 `금융 서비스 개발 실무 경험이 있는 지원자를 찾아줘`를 평가했다. 프로필은 기존 더미 프로필을 사용했고, 문서가 없는 지원자는 의미 검색 불완전 안내 대상이다. 이후 근거 선택과 개인정보 처리 등이 수정되어 이 결과는 최종 코드의 재현성 증거가 아니다.

- 키워드 후보 7명, 임베딩을 결합한 후보 7명. 양쪽 모두 정답 3명을 후보에 포함했다. 이 사례에서는 임베딩으로 추가된 정답이 없었다.
- 같은 프로세스에서 최종 검색을 세 번 반복한 결과는 모두 정답 3명이며, 지정된 나머지 5명은 반환되지 않았다.
- 모델 호출은 첫 요청 2회, 이후 각 1회였다. 이후 요청에서는 동일한 후보 판정을 메모리에서 재사용했다.
- 세 요청의 모델 입력 토큰은 12,081개, 출력 토큰은 438개였다. 임베딩 연산은 이 토큰 수에 포함되지 않는다.
- 이 평가는 인원이 적고 질문이 하나다. 같은 프로세스의 결과이며 재시작 또는 다른 프로세스에서도 같은 판정이 나온다는 뜻은 아니다.

실제 모델과 내부 임베딩 서비스가 준비된 환경에서 재실행:

```bash
cd ai
LANGSMITH_TRACING=false LLM_EVAL=true NCS_EMBED_URL=http://127.0.0.1:8002 uv run pytest -s -q tests/eval/test_profile_embedding_eval.py
```

실제 모델 평가에서는 가상 지원서 내용이 설정된 모델 제공자에게 전송된다. 임베딩 서비스는 내부망에서 실행한다.

## 개발 스냅샷 64명 부분 평가

도입 전에는 네 가지 질문을 각각 세 번 검색했다. 도입 후에는 기존 문서 64명 중 이재희, 강준서, 박재현, 이도윤 네 명만 문서별 1차 추출, 2차 검토와 변경 항목의 근거 검증을 거쳐 새 프로필과 임베딩을 만들었다. 나머지 지원자는 기존 프로필 또는 원문 검색을 사용했고, 각 검색 질문은 한 번씩 실행했다. 전체 워커 평가가 아니라 동일한 추출 함수와 프로필 변환 함수를 이용한 부분 평가다.

| 검색 사례 | 도입 전 결과 수 | 도입 후 결과 수 | 지정 사례 |
| --- | --- | --- | --- |
| PG사 9곳 결제 연동 | 4, 4, 4 | 4 | 지정된 포함 대상 발견 |
| 결제 서비스 실무 | 19, 24, 19 | 32 | 이전에 세 번 빠진 포함 대상을 발견했고 지정된 제외 대상은 빠짐 |
| 정산 배치 개선 | 8, 8, 7 | 11 | 지정된 포함 대상 발견 |
| Kafka 장애 전파 방지 | 16, 16, 20 | 21 | 이전 두 번 빠진 포함 대상을 발견 |

네 명의 1차 사실 수와 검토 후 사실 수는 각각 28에서 39, 17에서 19, 13에서 18, 5에서 5였다. 달라진 문장은 표현 수정도 포함하므로 숫자 차이를 정확한 누락 회수로 해석하지 않는다. 이 실행은 분석과 검색을 합쳐 모델 호출 38회였다.

64명 전체에 대한 정답이 없어 전체 재현율과 정밀도를 계산할 수 없다. 네 명만 다시 분석했으며, 나머지 프로필의 임베딩 부족 안내가 표시됐다. 도입 전후에는 모델 지시문과 전달 문맥도 달라져 결과 변화를 특정 변경 하나의 효과로 단정할 수 없다. 도입 후 검색은 각 질문을 한 번 실행했으므로 이 표로 반복 안정성을 판정할 수 없다.

## 근거 검토 표본

한 지원자의 2차 검토 표본에서 `중복 승인 0건`이 원문 다른 부분에 있었음을 확인했다. 초기에는 사실의 첫 인용이 해당 수치를 담지 않아 잘못된 근거처럼 보였다. 변경 항목은 각 원문 인용을 따로 검토하고, 뒷받침된 인용 또는 가까운 원문의 연속 구간을 골라 저장하도록 보완했다. 모델 판정이므로 표본 검증만으로 모든 추가 사실이 정확하다고 보장할 수 없다.

## 동일한 10명으로 변경 전후 비교

64명 중 기존 지정 사례를 포함해 10명을 선택했다. 변경 전 코드는 현재 작업을 시작하기 전 Git 버전에서, 변경 후 코드는 동일한 10명의 서류에 공고 기준 없이 분석 그래프의 2차 검토와 근거 검증을 수행하고 프로필을 임베딩한 상태에서 실행했다. 두 실행 모두 동일한 다섯 질문을 한 번씩 사용했다. 전체 64명이 아닌 선택된 표본이며 무작위 추출은 아니다.

도입 전 비교에 사용한 임시 복사본의 AI 소스 163개는 현재 브랜치의 기준 커밋 `7e78b52f43b8`과 바이트 단위로 일치했다. 더미 문서 스냅샷과 정답 자료는 SHA-256으로 연결했고, 도입 후 10명의 검토 결과는 별도 스냅샷으로 고정했다. 추가 반복 평가의 설정은 `gpt-6-luna`, temperature 0, function calling과 BGE-M3다. 임시 복사본과 일치한 소스 확인은 당시 모델 제공자 설정 전체까지 증명하지는 않는다.

| 사례 | 정답 | 변경 전 | 변경 후 |
| --- | ---: | --- | --- |
| PG사 9곳 연동 | 1명 | 1명 전원 발견 | 1명 전원 발견 |
| 정산 배치 시간 단축 | 2명 | 1명 발견, 1명 누락 | 2명 전원 발견 |
| Kafka 장애 전파 방지 | 5명 | 2명 발견, 3명 누락 | 5명 전원 발견 |
| 결제 서비스 실무 | 지정된 포함 및 제외 사례 | 포함 사례 1명 누락, 제외 사례는 제외 | 포함 사례 발견, 제외 사례는 제외 |
| 금융 서비스 개발 실무 | 지정된 포함 및 제외 사례 | 포함 사례 1명 누락, 제외 사례는 제외 | 포함 사례 발견, 제외 사례는 제외 |

정답을 모두 확인한 위 세 사례에서는 변경 후 정답 외의 지원자는 반환되지 않았다. 나머지 두 사례는 전체 정답이 아닌 일부 확인 사례만 있으므로 전체 정밀도를 계산하지 않았다. 단일 실행이므로 이 표는 모델 판정의 반복 안정성을 증명하지 않는다.

변경 전은 검색 다섯 건에 모델을 10회 호출했다. 변경 후는 10명의 지원서 분석과 검색 다섯 건을 합쳐 95회 호출했고, 입력 토큰 136,326개와 출력 토큰 28,759개가 기록됐다. 변경 전 검색 다섯 건에는 입력 토큰 25,715개와 출력 토큰 1,354개가 사용됐다. 서로 수행한 작업 범위가 달라 검색 한 번의 비용 비교로 해석하면 안 된다. 모델 가격과 임베딩 서버의 계산 비용은 포함하지 않는다.

변경 전 두 사례에서 누락된 정답은 이미 키워드 검색 후보에 있었다. 변경 후에는 프로필, 원문과 임베딩의 근거를 각각 최대 세 개씩 보존하고 판정에 주변 문맥을 제공했다. 모델 지시문, 프로필과 근거 구성이 함께 바뀌었으므로 개선 효과를 특정 요소 하나에 귀속할 수 없다.

| 결제 서비스 실무 | 6/8 | 8/8 |

확인된 제외 사례는 두 실행 모두 반환되지 않았다. 결제와 금융 질문에는 긍정과 부정 집계에서 제외한 미확정 사례가 각각 한 명 있으므로 위 수치로 전체 정밀도를 계산하지 않는다. 검색만 비교하면 도입 전 다섯 건은 모델 10회 호출, 입력 25,721토큰과 출력 1,349토큰이었다. 도입 후 다섯 건은 모델 10회 호출, 입력 53,428토큰과 출력 2,821토큰이었다. 도입 후의 프로필 분석과 임베딩 계산 비용은 포함하지 않았다. 질문마다 한 번씩 비교한 수치이며 반복 안정성을 보장하지 않는다.

## 코드 검사와 운영 적용

불완전 검색 회귀 테스트를 추가한 당시 다음 검사를 통과했다. 이 검사는 위 실제 모델 비교를 다시 실행한 결과가 아니다.

- `uv run ruff check`, `uv run ruff format --check`, `uv run mypy` 통과.
- `uv run pytest`: 1,872개 통과, 26개 건너뜀. 실제 모델 평가는 기본 실행에서 건너뛴다.
- 의미 검색에 누락이 있으면 공고 기준의 전체 최고 결과나 전원 미충족을 확정하지 않는 회귀 테스트 통과.
- Alembic 단일 헤드 `d1386ab958ed` 확인. 테스트 DB에서 마이그레이션과 모델 일치 검사 통과.
- `docker compose -f compose.production.yaml config --no-env-resolution --no-interpolate --quiet` 통과. 실제 임베딩 이미지 빌드와 운영 배포는 수행하지 않았다.

평가 자료와 재실행 도구를 추가한 뒤에는 Ruff 검사, 포맷 검사, mypy와 전체 pytest를 다시 실행했다. pytest는 1,875개 통과, 29개 건너뜀이며 실제 모델 평가는 기본 검사에서 건너뛴다. 실제 모델 검색, 동일 실행 추출, 임베딩 기준 실험은 별도로 실행했다.

운영 적용 시에는 마이그레이션을 적용하고 내부 임베딩 서비스를 준비한 뒤 기존 프로필의 색인을 채운다. 저장된 기존 분석에는 2차 검토가 자동으로 소급되지 않는다. 새 검토 결과가 필요하면 기존 재분석 경로를 사용한 후 색인을 확인한다.

```bash
cd ai
uv run alembic upgrade head
uv run python scripts/profile_embeddings.py --company-id <기업-UUID> --recruitment-id <채용-UUID>
```

일괄 색인은 프로필마다 커밋하므로 중간 실패 시 완료한 색인은 유지된다. 서비스 복구 후 같은 명령으로 다시 실행할 수 있다. 의미 검색의 백그라운드 색인 복구는 작업이 끝난 후 다시 검색해야 결과에 반영될 수 있다. 유사도 기준의 범용성과 최종 코드의 독립 실행 반복 안정성은 후속 평가 항목이다.

## 10명 표본의 추가 반복 평가

같은 10명의 2차 검토 결과를 고정하고 `gpt-6-luna`와 BGE-M3로 다섯 질문을 각각 세 번씩 두 방식으로 실행했다. 새 판정 기억 방식은 매 요청마다 도구 묶음을 새로 만들고, 공유 방식은 같은 질문의 세 요청이 판정 기억을 공유한다. 두 방식 모두 같은 프로세스에서 실행했다. 서로 다른 프로세스의 반복을 측정한 결과는 아니다.

| 질문 | 새 판정 기억 결과 수 | 공유 판정 기억 결과 수 | 새 판정 기억의 결과 변동 |
| --- | --- | --- | --- |
| PG사 9곳 연동 | 1, 1, 1 | 1, 1, 1 | 없음 |
| 결제 서비스 실무 | 9, 9, 9 | 9, 9, 9 | 없음 |
| 정산 배치 시간 단축 | 2, 2, 2 | 2, 2, 2 | 없음 |
| Kafka 장애 전파 방지 | 5, 5, 5 | 5, 5, 5 | 없음 |
| 금융 서비스 개발 실무 | 8, 7, 8 | 9, 9, 9 | 한 명이 한 번 빠짐 |

정답이 정리된 세 질문은 여섯 번 모두 정답을 빠뜨리지 않았고 정답 외의 지원자도 반환하지 않았다. 결제와 금융 실무는 기존 지정 사례 외에 긍정 사례를 각 8명으로 보강하고, 해당 여부가 모호한 한 명은 미확정으로 뒀다. 결제 질문의 여섯 실행은 확인된 긍정 사례를 모두 찾았고 확인된 제외 사례를 반환하지 않았다. 금융 질문에서는 새 판정 기억의 한 실행에서 긍정 사례 성혜린이 빠졌고, 확인된 제외 사례는 반환되지 않았다. 세 번 모두 검색 조건과 후보 명단은 같았다. 누락 당시 모델에 전달된 정확한 내용과 판정은 기록되지 않아 원인은 확정하지 못했다. 이후 같은 검색 조건을 고정한 별도 추적에서는 이력서의 이체 업무와 PG 연동 근거가 전달됐고 세 번 모두 포함됐다. 이 추가 추적의 세 모델 입력 해시는 같았다.

새 판정 기억의 15회 검색은 모델 호출 30회, 입력 155,190토큰, 출력 8,453토큰과 총 111.13초였다. 공유 방식의 15회는 호출 20회, 입력 87,606토큰, 출력 3,936토큰과 총 70.47초였다. 공유 방식은 질문마다 첫 요청에 2회, 이후 각 1회 호출했다. 분석과 임베딩 생성은 이 검색 비용에 포함하지 않는다. 시간은 해당 로컬 환경의 단일 측정이다.

## 유사도 기준과 원문 근거

정답이 정리된 세 질문에 원 요청 문장을 그대로 임베딩해 유사도 기준 0.25, 0.30, 0.35, 0.40, 0.45, 0.50을 비교했다. 의미 검색 단독에서도 여섯 기준 모두 정답 후보를 놓치지 않았다. 0.35에서는 세 질문 모두 10명이 의미 검색 후보였고, 기존 키워드 검색도 세 질문 모두 10명을 후보로 모았다. 0.50에서는 PG와 Kafka 의미 검색 후보가 각각 6명으로 줄었고 정답은 유지됐다. 키워드와 결합한 후보는 모든 기준에서 10명이었다. 이 표본에서는 기준 조정으로 통합 후보의 누락이나 크기가 달라지지 않아 일반적인 최적 기준을 고를 수 없다. 실제 검색의 모델 생성 조건은 원 요청 문장과 다를 수 있다.

재실행 도구가 기록한 첫 검색 순서에서 정답의 위치는 PG가 10번째, 정산이 1번째와 8번째, Kafka가 2번째, 3번째, 5번째, 6번째와 8번째였다. 이 순서에서 앞 5명만 검토한다고 가정하면 각각 정답 1명, 1명, 2명을 놓친다. 현재 코드는 5명으로 자르지 않는다. 이 실험은 상한을 낮췄을 때의 영향을 보여 주며 모델 호출 예산이 부족할 때의 실제 누락률을 측정한 것은 아니다.

이후 결제와 금융 실무의 확인된 포함 사례를 각각 8명으로 보강해 다섯 질문을 다시 측정했다. 0.35에서는 의미 검색과 통합 검색 모두 확인된 포함 사례를 놓치지 않았다. 0.45와 0.50의 금융 질문, 0.50의 결제 질문에서는 의미 검색만 사용할 때 이재희가 빠졌지만 키워드를 결합한 결과에는 포함됐다. 이 두 질문에서 한 명씩은 조건의 해석이 불명확해 정답에서 제외하지 않고 미확정으로 뒀다. 기준을 높일수록 의미 검색 후보가 줄더라도 관련 지원자를 놓칠 수 있는 표본 사례다.

세 질문에 대한 10명 전체의 표본 정답과 나머지 두 질문의 확인 및 미확정 사례를 `dev_search_ten_gold.json`에 고정했다. 두 질문의 미확정 사례는 결제 로그 수집과 이벤트 분리 경험을 해당 조건에 포함할지 해석이 갈리는 지원자다. 긍정과 미확정 사례 및 해당 제외 사례에는 원문 인용을 붙였다. 10명의 저장된 검토 결과에 포함된 근거 228개는 모두 표시된 문서에서 확인됐다. 이는 원문에 인용이 있는지 확인한 수치이며, 228개 주장이 모두 인용에서 논리적으로 뒷받침된다는 검증은 아니다.

새로 실행한 1차 추출과 별도 실행에서 저장된 2차 검토 결과를 비교했을 때, 세 질문의 긍정 사례 8개에서 지정한 원문 근거는 양쪽 모두에 있었다. 두 결과는 별도 모델 실행이므로 전체 사실 수의 차이를 2차 검토가 회수한 누락 수로 해석하지 않는다. 1차 추출 21회 호출에 입력 20,000토큰, 출력 11,452토큰과 45.05초가 들었다.

원시 수치와 범위는 `dev_search_ten_results.json`, 고정된 검토 결과는 `dev_search_ten_reviews.json`에 있다. 모델의 재확인에 넘길 문장과 주변 문맥을 포함해 다시 측정하려면 다음 명령을 실행한다. 기존 스냅샷을 색인하므로 서류 전체를 다시 분석하지 않으며 실제 모델 호출과 임베딩 계산이 발생한다.

```bash
cd ai
LANGSMITH_TRACING=false LLM_EVAL=true NCS_EMBED_URL=http://127.0.0.1:8002 uv run pytest -s -q tests/eval/test_dev_search_ten_eval.py::test_ten_candidate_search_with_real_model
```

같은 스냅샷의 유사도 실험은 위 명령의 테스트 이름을 `test_ten_candidate_similarity_thresholds`로 바꿔 실행한다. 문서를 새로 분석하는 동일 실행 비교는 `test_ten_document_extraction_with_real_model`로 실행하며, 더 많은 실제 모델 호출이 발생한다.

검색 재실행 도구는 재확인 모델 호출이 실제로 발생한 경우 입력과 해시, 후보 번호별 모델 응답도 기록한다. 판정 기억을 재사용한 경우에는 모델 호출 기록이 없다. 이 기록은 가상 지원자 평가용이며, 위의 이전 누락 당시 응답을 복원하는 것은 아니다.

기존 2차 검토 자체의 모델 판정 정확도, 금융 및 결제 질문의 미확정 사례와 표본 밖 유사도 기준은 이 실험으로 확정하지 못했다.

## 동일한 1차 추출 결과를 사용한 2차 검토

기존 검토 스냅샷과 별개로 10명의 문서 21건을 다시 분석했다. 각 문서에서 1차 추출과 그 결과를 입력으로 받은 2차 검토를 같은 실행 안에서 비교했다. 1차 사실 174건이 검토 후 212건이 됐다. 문장 기준으로 새로 나타나거나 표현이 달라진 항목은 42건이고, 이전 표현이 사라지거나 바뀐 항목은 4건이다. 표현 변경이 포함되므로 이를 누락된 사실 42건의 회수나 잘못된 사실 4건의 제거로 해석하지 않는다.

검토 후 인용 218건은 모두 해당 문서의 원문에서 확인됐으며, 기존 세 질문의 긍정 근거 8개는 1차와 2차에 모두 있었다. 인용의 원문 존재는 주장이 인용으로 뒷받침되는지에 대한 독립적인 판정이 아니다. 이 실험은 모델 호출 64회, 입력 69,208토큰, 출력 20,181토큰과 129.68초를 사용했다. 원시 집계는 `dev_search_ten_results.json`의 `same_run_extraction`에 있다.

재실행용 평가 코드로 같은 10명을 다시 측정한 결과는 1차 188건, 2차 242건이었다. 새로 나타나거나 바뀐 표현은 70건, 사라지거나 바뀐 표현은 16건이며, 검토 후 인용 244건은 해당 문서에서 모두 확인됐다. 보강된 다섯 질문의 긍정 근거 24개는 1차와 2차에 모두 있었다. 별도 실행에서 모델 출력이 달라 사실 수가 달라졌으므로 두 실행을 합산해 정확도를 계산하지 않는다. 두 번째 측정은 모델 67회 호출, 입력 73,322토큰과 출력 23,343토큰을 사용했고 후보별 집계 시간의 합은 269.78초였다.

다른 실행에서 강준서, 김다인, 이재희 세 명의 새 문장 또는 바뀐 문장 26개를 인용과 직접 대조했다. 25개는 인용이 주장과 역할을 뒷받침했다. 이재희의 `지원했다`는 표현 하나는 인용문에 직접 적혀 있지 않아 지원서라는 문서 맥락이 필요하다. 명백히 원문과 모순되는 주장은 이 26개에서 찾지 못했지만, 한 차례 검토한 작은 표본이므로 전체 사실의 정확도로 일반화할 수 없다. 이 세 명에 대한 실행은 모델 호출 21회, 입력 23,130토큰, 출력 7,474토큰과 49.67초였으며, 항목별 자료와 검토 판정은 `dev_search_ten_results.json`에 있다.

고정된 검토 스냅샷으로 재실행용 평가 코드 자체를 검증한 두 번째 30회 검색에서는 다섯 질문 모두 같은 방식 안에서 반복 결과가 같았다. 앞선 실험의 금융 질문에서 한 번 누락된 사례가 있으므로 두 번째 결과만으로 모델 판정이 항상 일정하다고 볼 수 없다. 질문별 첫 검색의 후보 근거와 준비된 문맥은 `dev_search_ten_trace.json`에 있다.

두 번째 측정의 질문별 첫 검색에서 확인된 긍정 사례 24건을 단계별로 추적했다. 24건 모두 후보와 최종 결과에 있었다. 평가 자료에 지정한 인용과 같은 구절은 검색 근거에서 6건, 주변 문맥까지 확장한 자료에서는 2건 발견하지 못했다. 지정한 인용 외의 관련 근거가 있을 수 있으므로 이 수치는 근거 없는 결과 2건이라는 뜻이 아니다. 개별 사례와 단계별 결과는 `dev_search_ten_results.json`의 `harness_first_run_anchor_trace`에 기록했다.

| 전체 정답이 있는 질문 | 후보에서 발견한 정답 | 후보 중 정답 비율 | 최종 결과에서 발견한 정답 | 최종 결과 중 정답 비율 |
| --- | --- | --- | --- | --- |
| PG사 9곳 연동 | 1/1 | 1/10 | 1/1 | 1/1 |
| 정산 배치 시간 단축 | 2/2 | 2/10 | 2/2 | 2/2 |
| Kafka 장애 전파 방지 | 5/5 | 5/10 | 5/5 | 5/5 |

이 표는 각 질문의 첫 검색과 정답이 정리된 가상 지원자 10명만을 대상으로 한다. 후보 중 정답이 아닌 지원자도 다음 단계의 재확인을 위해 남겨 둔 것이며 최종 결과의 오탐과 구분한다.

두 측정은 서로 다른 프로세스와 임시 DB에서 같은 10명 스냅샷을 다시 색인해 실행했다. 새 판정 기억으로 실행한 첫 검색끼리 비교하면 네 질문은 같은 지원자를 반환했고 금융 질문은 첫 측정 8명, 두 번째 9명으로 달랐다. 차이인 박재현은 금융 서비스 개발 실무에 포함할지 미확정인 경계 사례다. 매 실행에서 DB 항목과 벡터를 새로 만들어 정확히 같은 모델 입력을 강제한 실험은 아니므로 이 차이를 특정 원인에 귀속할 수 없다.

금융 조건을 고정하고 재확인 모델에 보낸 입력 해시까지 같은 상태에서 열 번 추가 실행했다. 열 번 모두 같은 지원자를 반환했고 성혜린도 포함됐다. 다만 세 후보는 충족 판정은 같아도 모델이 선택한 근거 번호가 달랐다. 같은 입력에서도 근거 선택이 달라질 수 있음을 관찰했지만, 앞선 성혜린 누락의 입력과 응답을 기록하지 못했으므로 그 누락의 직접 원인으로 단정하지 않는다. 판정 기억을 재사용하는 동안에는 저장된 근거와 판정을 다시 쓴다.
