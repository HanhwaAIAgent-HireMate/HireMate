# 섹션과 부품 고르기

## 섹션

리포트는 요약 한 단락 + 섹션 2~7개다. 섹션마다 읽을 점(takeaway) 한 문장과 부품 1~3개를 둔다.

1. 한눈에 보기: 전체 그림 (총점 구성, 전체 안의 위치, 핵심 지표)
2. 영역마다 섹션 하나 (area에 영역 id): 그 영역의 점수와 항목 판정만 그린다
3. 요청 관점 (있을 때): 관점과 관련된 항목 판정과 근거
4. 정리: 공통점 · 차이 · 다음 전형에서 확인할 점 (evidence 또는 text)

takeaway는 그 섹션 그림에서 읽을 점이다. 항목끼리 높다 · 낮다를 쓰기 전에 count_values로 비율을 세어 확인하고,
비율 값을 같이 쓴다. 예: "세 명 모두 자격요건 항목은 고르게 충족했고, 차이는 테스트 코드 한 항목이에요."

## 제목

섹션과 부품 제목은 그림이 무엇을 보여 주는지 담당자가 쓰는 말로, 15자 안팎의 명사구로 쓴다.
읽는 사람이 제목만 보고 무엇을 세었는지 알 수 있어야 한다.

- 무엇을 · 누구를 세었는지 드러낸다. '구성', '비교', '정리'처럼 뜻이 넓은 말 하나로 끝내지 않는다.
- 값 key 이름(document.criterion.Q-05), 항목 코드만 있는 제목(Q-05), 개발 용어('선 위', '경계 그룹',
  '판정 교차', '조각 지표')는 쓰지 않는다. 항목은 짧은 이름으로 쓴다.
- 읽을 점은 제목이 아니라 takeaway에 쓴다. 제목에 결론을 넣지 않는다.

| 좋은 제목 | 피할 제목 |
|---|---|
| 항목별로 걸린 지원자 | 항목 판정 |
| 지원자별 점수와 판정 | 값 정리 |
| 두 판정을 함께 본 인원 | 판정 교차 |
| 영역별 점수로 본 총점 | 총점 구성 |
| 테스트 코드 항목 판정 | Q-05 |
| 필수 조건을 모두 충족한 지원자 | 선 위 지원자 |

## 먼저 읽는 사람이 할 일을 정한다

부품은 자료 모양이 아니라 읽는 사람이 그림에서 할 일로 고른다. 그림이 아니어도 되면 그림을 쓰지 않는다.

| 읽는 사람이 할 일 | 부품 |
|---|---|
| 핵심 숫자 몇 개를 바로 본다 | kpi. 숫자 하나를 막대 하나로 그리지 않는다 |
| 전형 전체가 어디에 몰렸는지 본다 | distribution (split로 합격 · 불합격, reference로 평균선) |
| 전체가 몇 갈래로 나뉘는지 본다 (6갈래 이하) | donut. 값이 비슷한 갈래끼리 견줄 때는 bar나 숫자 |
| 두 판정이 엇갈린 인원을 본다 | cross |
| 그룹이 전체와 어떻게 다른지 본다 | share (같은 항목을 그룹 · 전체로 나란히) |
| 구성(구간 비율)이 그룹마다 어떻게 다른지 본다 | composition |
| 지원자마다 총점이 무엇으로 이루어졌는지 본다 | stacked |
| 지원자끼리 점수 한 가지를 견준다 | bar (reference로 평균선) |
| 지원자끼리 여러 관점의 비율을 한눈에 견준다 | rings |
| 지원자가 전체 안 어디쯤인지 본다 | position, 또는 distribution의 highlight |
| 여러 영역 점수의 모양을 견준다 (영역 3개 이상) | radar |
| 누가 어느 항목을 충족했는지 하나씩 본다 | matrix |
| 항목마다 판정 비율을 본다 | tally |
| 숫자와 판정을 한 줄에 정리한다, 항목이 많다 | table |
| 판단과 그 근거를 읽는다 | evidence (근거 id 필수) |

## 한 부품에는 한 가지만

- 만점이 다른 값을 한 부품에 섞지 않는다. 총점과 영역 점수는 stacked와 영역 섹션의 bar로 나눈다.
- 같은 자료를 두 번 그리지 않는다. matrix와 tally는 같은 항목을 다른 섹션에서 겹쳐 쓰지 않는다.
- 하나가 요점이면 그 하나만 드러낸다. 비교 대상 몇 명의 위치가 요점이면 전형 전체 분포에 highlight로 그 사람들만 표시한다.
- 의미가 있는 갈래가 7개를 넘으면 그림 대신 table로 정리한다.
- 한 리포트 안에서 같은 부품만 되풀이하지 않는다. 자료가 있으면 분포 · 도넛 · 교차표 · 비율 막대 · 구성 막대처럼 모양이 다른 부품을 섞는다.

## 피할 것

| 피할 것 | 대신 |
|---|---|
| 값 하나뿐인 막대, 두 조각뿐인 도넛 | kpi에 숫자로 |
| 비슷한 값끼리 견주는 도넛 | bar |
| 판정(충족 · 미충족)을 bar로 | matrix, tally |
| 항목 하나뿐인 matrix | evidence 한 줄 |
| 모든 값을 caption에 늘어놓기 | 요점 하나 (가장 큰 차이, 기준선과의 관계) |
| 그림에 없는 것을 caption에 쓰기 (넣지 않은 기준선 등) | 그린 것만 쓰기 |

색 · 범례 · 마우스를 올렸을 때 값 보기는 화면이 정한다. 설계서에는 색을 적지 않는다.

## caption

모든 시각화 부품에 '무엇을 보여 주는지' 한 줄을 쓴다. 예: "점선은 전체 평균이에요. 세 명 모두 평균 위에 있어요."
distribution에 highlight를 쓰면 무엇을 표시했는지 쓴다. 기준선(reference)을 넣지 않았으면 caption에 기준선을 말하지 않는다.
caption의 숫자는 묶음에 있는 값이나 그 부품이 그리는 값(비율 · 인원 · 상위 %)만 쓴다.
