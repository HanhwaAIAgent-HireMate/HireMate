# 멀티에이전트 기반 E2E 채용 자동화 플랫폼
## 제품 요구사항 정의서

기업별 전형 구성과 대화형 지원자 탐색을 지원하는 Human in the Loop 채용 서비스

작성일 2026년 10월 19일 | 작성자 정유민 | 대상 기획 담당자, 개발 담당자, 프로젝트 검토자

![서비스 구성도](assets/서비스_구성도.png)

### 1 문서 개요

본 문서는 기업이 필요한 전형을 조합하고, AI의 분석과 탐색 결과를 활용하여 채용을 운영하는 플랫폼의 제품 요구사항을 정의한다. 공고 작성, 지원 접수, 전형 진행, 담당자의 결정, 결과 안내, 최종 리포트를 하나의 흐름으로 연결하는 것이 MVP의 목표다.

AI가 제안한 후보군과 담당자가 확정한 채용 결과를 구분한다. AI는 근거를 제공하고 작업을 보조하며, 전형의 합격과 불합격은 담당자가 직접 결정한다.

| 운영 원칙 | AI 제안과 채용 결과 분리, 근거와 출처 제공, 담당자의 검토 후 게시와 발송 |

### 2 문제 정의 및 목표

기업마다 필요한 전형의 종류와 순서가 다르며, 같은 기업도 직무에 따라 채용 절차가 달라진다. 고정된 절차에 맞춘 시스템은 이러한 차이를 반영하기 어렵다. 또한 지원 문서, 평가 결과, 과제, 면접 기록이 분리되면 담당자가 지원자를 비교하고 판단 근거를 확인하는 데 반복적인 검토가 필요하다.

본 서비스는 전형을 공통 구조로 구성하고, 자료가 들어올 때 지원자 프로필을 갱신한다. 담당자는 자연어로 후보군을 찾고 조건을 좁히며, AI가 제시한 근거를 확인한 뒤 직접 결과를 결정한다.

| 목표 | MVP 성공 기준 |
|---|---|
| 기업별 채용 절차 구성 | 전형 이름과 순서를 자연어로 정하고 서류, 평가, 면접 유형으로 구성한다. |
| 지원자 탐색 효율 향상 | 조건에 맞는 후보군을 리스트에 표시하고 추가, 좁히기, 직접 편집을 지원한다. |
| 전형 간 정보 연결 | 지원 자료, 평가 결과, 면접 기록을 누적하고 서로 다른 자료의 근거를 함께 제시한다. |
| 담당자의 통제 유지 | AI 탐색은 채용 상태를 바꾸지 않으며 합격과 불합격은 담당자 버튼 조작으로만 결정한다. |
| 채용 업무의 연결 | 공고부터 안내 발송과 최종 리포트까지 하나의 채용 흐름을 완료한다. |

### 3 사용자 및 핵심 시나리오

| 사용자 | 주요 업무 | 대표 시나리오 |
|---|---|---|
| 채용 담당자 | 설정, 공고, 전형 구성, 검토, 결정, 안내 | 공고 작성 → 전형 구성 → 게시 → AI 탐색 → 직접 결정 → 안내 → 종료 |
| 면접관 | 질문 확인, 질문 추가, 답변 기록 | 이전 전형 확인 → 맞춤 질문 생성 → 면접 진행 → 질문별 답변 기록 |
| 지원자 | 공고 확인, 동의, 지원서 제출 | 자체 채용 페이지 확인 → 필수 자료 제출 → 결과 안내 수신 |

면접관의 계정 구분과 열람 범위는 별도 확정이 필요하다. 관리자용 정책 관리 화면은 현재 MVP 화면 범위에 포함하지 않는다.

### 4 범위

#### 4 1 포함 범위

- 회사 소개, 채용 공고 양식, 안내 메일 양식 등록과 PDF 참고 자료 관리
- 기업 양식을 이용한 공고 작성과 AI 수정안 확인 및 적용
- 자연어 전형 구성과 자체 채용 페이지 게시
- 공통 지원서와 필수 제출 항목 검증
- 지원 자료 분석, 서류 점수 산정, 근거가 포함된 지원자 프로필 생성
- 서류, 평가, 면접에 공통으로 사용하는 전형 화면
- 자연어 지원자 탐색, 분석, 비교와 선택 지원자 편집
- 외부 평가 결과와 과제 제출물 등록 및 해석
- 지원자별 면접 질문 생성과 질문별 답변 기록
- 담당자의 개별 및 일괄 결정과 전형 결과 확정
- 기업 양식 기반 안내 초안, 담당자 검토 및 발송
- 채용 종료 후 문서형 최종 채용 리포트 생성

#### 4 2 제외 범위

| 구분 | MVP에서 제외하는 기능 |
|---|---|
| 지원자 유입 | 외부 채용 플랫폼 자동 게시, 직접 소싱, 헤드헌팅 |
| 자체 평가 | 검사 시스템, 코딩테스트 플랫폼, AI 영상면접, 면접 영상 및 녹취 분석 |
| 외부 연결 | 모든 평가 업체 API 연동, 자동 면접 일정 조율 |
| 입사 이후 | 전자계약, 급여, HRIS 연동, 복잡한 온보딩 |
| 분석 및 탐색 UI | 고도화된 채용 Analytics, 자료 위치로 이동하는 출처 칩 |

외부 평가는 업로드와 수동 입력으로 결과를 가져온다. 출처는 텍스트로 제공하며, 최종 리포트는 차트 중심 대시보드가 아닌 요약 문서로 제공한다.

#### 4 3 범위 적용 원칙

공고는 항상 첫 단계이며 지원자를 평가하는 Stage와 구분한다. 이후에는 필요한 전형만 선택하고 같은 유형을 여러 번 사용할 수 있다. 예를 들어 공고 → 면접, 공고 → 서류 → 평가, 공고 → 서류 → 평가 → 평가 → 면접 → 면접을 모두 표현할 수 있다.

게시 후 전형 변경, 결과 확정 취소, 리포트 공유 정책은 부록의 확정 필요 항목으로 관리한다.

### 5 전체 시스템 구조

| 계층 | 주요 구성 | 책임 |
|---|---|---|
| 사용자 화면 | 대시보드, 공고 편집, 지원서, 공통 전형, 종료, 리포트 | 자료 입력, 탐색 결과 표시, 담당자 결정과 발송 |
| 업무 서버 | Spring 서버 | 채용과 전형 데이터 관리, 대상 및 권한 검증, 선택 편집과 결과 변경 실행 |
| 요청 조율 | Root Agent | Chat 의도와 대상을 해석하고 찾기는 검색 계획, 분석과 생성은 도구 루프로 처리 |
| 전문 처리 | 분석 Agent와 생성 Agent | 자료 분석 및 프로필 갱신, 공고와 질문 및 안내와 리포트 생성 |
| 공통 기반 | 지원자 프로필, 원문 자료, 조건 및 의미 검색 | 누적 정보를 검색하고 근거 문장과 출처를 제공 |

자료가 들어오는 시점에는 분석 Agent가 프로필을 갱신한다. Chat의 찾기 요청은 프로필에서 후보를 먼저 좁히고 필요한 Agent로 근거를 다시 확인한다. 분석과 생성 요청은 Root Agent가 도구와 Agent를 골라 부르며 근거를 모은다. 선택 편집은 Root Agent가 구조화된 명령으로 변환하고 서버가 검증하여 실행한다.

### 6 Agent 설계

| Agent | 실행 계기와 책임 | 주요 출력 |
|---|---|---|
| Root Agent | Chat 요청의 의도와 대상 판단, 찾기의 검색 계획, 분석과 생성의 도구 선택 | 실행 계획, 근거를 포함한 통합 응답 |
| Application Agent | 지원 접수 및 요청 시 지원 문서 분석 | 지원자 프로필, 근거와 출처, 서류 점수 |
| Assessment Agent | 평가 결과 및 과제 등록 시 분석 | 점수와 지표 해석, 제출물의 강점과 확인 사항 |
| Interview Agent | 질문 생성 요청 또는 답변 기록 | 맞춤 질문, 답변에서 확인된 점과 미확인 사항 |
| Posting Agent | 공고 화면의 AI 수정 요청 | 수정안, 전형 이름과 유형, 필수 제출 서류 |
| Communication Agent | 확정된 전형 결과의 안내 초안 작성 | 기업 양식과 필수 문구를 반영한 안내 초안 |
| Report Agent | 채용 종료 | 전형별 인원, 최종 결과, 주요 근거와 특이사항 요약 |

동일한 모델에 역할별 지시문, 도구, 출력 형식을 달리 적용한다. 화면에서 직접 요청한 공고 수정과 안내 작성은 해당 Agent를 호출하며, AI Chat 요청은 Root Agent가 조율한다. Root Agent는 자체적으로 지원자를 분석하거나 채용 상태를 변경하지 않는다.

### 7 기능 요구사항

우선순위 Must는 MVP 완료에 필요한 기능, Should는 핵심 흐름 완료 후 적용할 보완 기능이다. 점수 기준 등 정책이 필요한 항목은 기능을 구현하더라도 부록의 정책 확정을 함께 확인한다.

#### 7 1 채용 준비 및 지원 접수

| ID | 기능 | 요구사항 | 우선순위 |
|---|---|---|---|
| FR-01 | 기업 설정 | 설정은 회사 소개, 채용 공고, 안내 메일의 세 영역으로 구성한다. 조직 문화, 인재상, 복지와 PDF 참고 자료를 등록한다. | Must |
| FR-02 | 공고 초안 | 기업 공고 양식으로 편집 화면을 열고 회사 소개, 복지, 필수 안내 문구를 채운다. 직무 정보는 직접 또는 AI 요청으로 작성한다. | Must |
| FR-03 | AI 수정안 | AI가 바꾼 부분을 표시하고 담당자가 확인한 후 적용한다. 전형 절차, 필수 제출 서류, 필수 문구는 고정 칸으로 구분하며 담당자의 요청으로만 바꾼다. | Must |
| FR-04 | 전형 구성 | 자연어로 전형 추가, 삭제, 순서 변경을 지원한다. 이름을 유지하고 DOCUMENT, ASSESSMENT, INTERVIEW 유형으로 분류한다. 모호한 유형은 되묻는다. | Must |
| FR-05 | 공고 게시 | 접수 기간, 공고명과 채용 요약을 확인한 뒤 담당자가 게시한다. 자체 채용 페이지를 생성하고 기간 종료 시 첫 전형을 시작한다. | Must |
| FR-06 | 공통 지원서 | 이름, 이메일, 연락처, PDF 이력서와 자기소개서, 개인정보 및 AI 활용 동의를 필수로 받는다. 자격증 텍스트와 PDF 포트폴리오는 기본 선택 항목이다. | Must |
| FR-07 | 필수 항목 검증 | 공고에서 추가로 요구한 서류를 지원서의 필수 항목으로 반영한다. 누락되면 제출을 막고 해당 항목으로 이동한다. | Must |
| FR-08 | 자료 사전 분석 | 지원 접수 시 Application Agent가 자료를 분석하고 근거와 출처를 프로필에 저장하며 서류 점수를 산정한다. | Must |
| FR-09 | 채용 대시보드 | 진행 상태와 전형 흐름을 표시하고 종료된 전형은 회색으로 구분한다. 채용을 누르면 현재 단계로 이동하며 로고로 대시보드에 돌아온다. | Must |

#### 7 2 전형 화면과 대화형 탐색

| ID | 기능 | 요구사항 | 우선순위 |
|---|---|---|---|
| FR-10 | 공통 전형 화면 | 전체 지원자, 선택 지원자 또는 지원자 카드, AI Chat의 3단 구조를 사용한다. 전형 이름, 종류, 인원과 결정 현황을 표시한다. | Must |
| FR-11 | 지원자 카드 | 서류는 문서와 근거 하이라이트 및 AI 분석, 평가는 결과와 제출물, 면접은 맞춤 질문과 답변 기록을 보여 준다. 관련 자료와 메모를 확인한다. | Must |
| FR-12 | Chat 대상 지정 | 현재 채용과 전형을 기본 범위로 사용한다. @멘션을 입력창 칩으로 넣고 해제할 수 있다. 대상이 없으면 현재 전형 전체 지원자를 기준으로 한다. | Must |
| FR-13 | 요청 조율 | Root Agent가 지원자 찾기, 분석 및 생성, 선택 지원자 편집을 구분한다. 찾기는 정해진 검색 순서로, 분석 및 생성은 도구 루프로 처리하고 결과를 조합하여 응답한다. | Must |
| FR-14 | 자연어 탐색 | 조건 검색과 의미 검색으로 후보를 좁힌 후 근거를 재확인한다. 결과를 리스트의 AI 표시, 선택 지원자 영역, Chat 요약에 함께 반영한다. | Must |
| FR-15 | 탐색 결과 편집 | 찾아줘는 새 결과로 교체하고 이전 선택으로 되돌릴 수 있다. 추가해줘는 기존 결과에 더하며 그중이라는 요청은 현재 선택 안에서 좁힌다. | Must |
| FR-16 | 직접 넣기와 빼기 | 리스트와 선택 카드의 +와 -로 편집한다. Chat의 편집 명령은 서버가 대상과 권한을 검증한 후 실행한다. 빼기는 불합격 처리가 아니다. | Must |
| FR-17 | 대화형 분석 | 특정 지원자 의견과 비교는 근거 및 출처와 함께 답한다. 여러 전형 자료가 필요하면 모두 확인한다. 설명 요청으로 후보군을 바꾸지 않는다. 없는 자료를 근거로 결과를 만들지 않는다. | Must |
| FR-18 | 리스트 표시 | 이름, 경력 연수와 마지막 회사 또는 신입을 표시한다. 평가 전형은 평가 점수를 붙인다. 스크롤로 이어 불러오고 각 영역의 전체 인원을 표시한다. | Must |

대상이 모호한 편집 요청은 실행 전에 되묻는다. 선택 지원자에 넣는 동작과 합격 또는 불합격 결정은 별개로 처리한다. AI Chat의 채용 결과 변경 요청은 합격 및 불합격 버튼을 안내하며 실행하지 않는다.

#### 7 3 검토 표시와 담당자 결정

| ID | 기능 | 요구사항 | 우선순위 |
|---|---|---|---|
| FR-19 | 서류 검토 순서 | 서류 점수순으로 전원을 표시한다. 기준 통과는 굵게, 미달은 회색으로 구분하고 두 그룹 사이에 글자 없는 선을 둔다. 점수 숫자는 카드에 표시하지 않는다. | Must |

| FR-21 | AI와 결정 표시 | AI 선택은 결정 색과 겹치지 않는 색 테두리, 직접 추가는 테두리 없이 표시한다. 미결정은 흰색, 합격은 연한 초록, 불합격은 연한 빨강 배경을 사용한다. | Must |
| FR-22 | 일괄 결정 | 체크박스와 전체 선택으로 검토 대상을 정하고 하단 합격 또는 불합격 버튼으로 결정한다. 체크 인원을 표시하고 체크가 없으면 버튼을 비활성화한다. | Must |
| FR-23 | 결정 반영과 복구 | 개별 결정은 확인 창 없이 반영하고 방금 한 결정을 되돌릴 수 있다. 결정자는 선택 영역에서 빠지고 전체 리스트에 남는다. 복구하면 선택 영역으로 돌아온다. | Must |
| FR-24 | 전형 결과 확정 | 확정 전에 합격과 불합격 인원 및 미결정 포함 인원을 확인한다. 합격자만 다음 전형 대상이 되며 나머지와 미결정자는 불합격으로 확정한다. | Must |

#### 7 4 표시 규칙

AI 선택 테두리는 선택 영역에 있는 동안 유지한다. 선택 영역에서 제거하거나 새 탐색으로 교체하거나 결과를 결정하면 테두리를 제거한다. AI 선택과 직접 추가를 설명하는 글자 라벨, 결정 상태 칩, 결정 아이콘은 카드에 추가하지 않는다.

서류 점수 기준은 담당자의 검토 순서를 돕는 기준이다. 기준 미달이라는 이유로 자동 불합격 처리하지 않으며 담당자는 전체 지원자의 자료를 확인할 수 있다. 합격과 불합격 버튼은 화면 하단에 두고 선택 카드와 지원자 카드 안에 중복 배치하지 않는다.

### 8 AI 통제 및 검증 요구사항

이 절의 통제는 제품 동작의 경계를 정의한다. 별도의 AI Gateway 제품, 정책엔진 또는 특정 오케스트레이션 프레임워크 채택은 본 문서에서 확정하지 않는다.

| 구분 | 요구사항 |
|---|---|
| 조회 범위 | 현재 기업, 채용, 전형과 지정된 지원자를 기준으로 조회한다. 다른 기업의 데이터는 검색 대상에 포함하지 않는다. |
| 근거 검증 | 분석과 탐색 결과에 근거 문장과 출처를 제공한다. 프로필 검색 후 후보의 원문 근거를 재확인한다. |
| 미확인 정보 | 자료가 없거나 근거가 부족하면 그 사실을 구분하여 표시한다. 미확인 정보를 사실로 채우지 않는다. 세부 응답 문구는 확정이 필요하다. |
| 차별 조건 | 나이, 성별, 출신 지역, 혼인 여부, 신체 조건 등 부적절한 조건의 탐색을 차단하고 안내한다. 구체적인 목록과 문구는 법무 검토 후 확정한다. |
| 실행 경계 | AI는 선택 편집 명령만 서버로 전달한다. 합격과 불합격 결정, 결과 확정, 게시와 발송을 AI가 독자적으로 수행하지 않는다. |
| 외부 문서 | 제출 문서와 URL의 내용은 분석 자료로 취급한다. 문서 안의 지시문으로 도구 권한이나 채용 상태가 바뀌지 않도록 검증한다. |
| 도구 루프 | 조회 도구와 분석 및 생성 Agent만 쓰고, 조회 범위는 코드가 정하며 모델 호출 횟수에 상한을 둔다. |

### 9 Human in the Loop

| 작업 | 처리 정책 | 담당자의 개입 |
|---|---|---|
| 자료 분석과 프로필 갱신 | 자료 유입 시 자동 분석 | 근거 및 원문 검토 |
| 공고 수정과 안내 초안 | AI가 수정안 또는 초안 생성 | 변경 확인과 적용, 게시 또는 발송 |
| 지원자 탐색 | 선택 영역과 화면 표시만 변경 | 후보군 확인과 직접 편집 |
| 선택 지원자 넣기와 빼기 | 대상과 권한 검증 후 실행 | 확인 창 없이 편집, 모호한 대상은 재질문 |
| 합격과 불합격 결정 | 체크 후 하단 버튼으로 처리 | 담당자 직접 실행, 직후 되돌리기 |
| 전형 결과 확정 | 미결정자를 포함한 인원 확인 | 확인 창에서 확정 |
| 안내 및 종료 | 확정 결과 기반 초안 생성 | 초안 검토와 발송 후 전형 또는 채용 종료 |

개별 결정의 되돌리기와 전형 결과 확정 이후의 취소는 서로 다른 기능이다. 후자의 허용 시점과 권한은 별도 확정 전까지 제품의 보장된 동작으로 간주하지 않는다.

### 10 도구 인터페이스 설계 초안

다음은 Agent와 업무 서버 사이에 필요한 논리적 도구 목록이다. 이름과 호출 규격은 설계 초안이며, MCP 도입 여부와 구체적인 구현 방식은 기술 설계에서 결정한다. 조회 및 생성과 상태 변경 실행을 분리한다.

| 도구 | 분류 | 역할과 실행 경계 |
|---|---|---|
| search_candidate_profiles | 조회 | 채용 및 전형 범위의 조건 검색과 의미 검색 |
| get_candidate_evidence | 조회 | 지원자 프로필과 원문 근거 및 출처 확인 |
| analyze_application | 분석 | 지원 문서 분석, 서류 점수와 프로필 생성 |
| analyze_assessment | 분석 | 평가 결과와 과제 해석 및 프로필 갱신 |
| generate_interview_questions | 생성 | 이전 전형 정보를 바탕으로 맞춤 질문 생성 |
| analyze_interview_answers | 분석 | 기록된 면접 답변 분석 및 프로필 갱신 |
| edit_candidate_selection | 작업 영역 변경 | 담당자의 명시적 편집 지시를 서버가 검증해 실행 |
| generate_posting_or_message | 생성 | 공고 수정안 또는 안내 초안 생성 |
| generate_recruitment_report | 생성 | 채용 종료 결과의 문서형 요약 생성 |

분석과 생성 요청에서는 Root Agent가 위 도구 가운데 필요한 것을 골라 부르며 edit_candidate_selection은 제공하지 않는다. 게시, 합격과 불합격 변경, 결과 확정, 실제 안내 발송은 담당자의 화면 조작을 받는 업무 API에서 실행한다. 위 도구에 자동 채용 결정 기능을 부여하지 않는다.

| NFR-09 | 확장성 | 같은 유형의 전형을 반복 구성하고 공통 화면과 Stage 모델을 유지한다. 역할별 Agent와 평가 입력 방식은 독립적으로 확장한다. |

### 13 핵심 업무 흐름

**채용 준비와 지원**: 담당자가 기업 설정을 등록하고 공고 양식을 연다. 직무 정보, 전형 절차, 추가 필수 서류를 직접 또는 AI로 작성한다. 수정안을 확인하고 접수 기간을 정해 게시한다. 지원자는 필수 자료와 동의를 제출하고 Application Agent가 프로필을 생성한다.

**전형 진행**: 접수 종료 후 첫 전형을 시작한다. 평가 결과와 면접 답변이 들어오면 해당 Agent가 프로필을 갱신한다. 담당자가 Chat으로 탐색하거나 분석을 요청하고 Root Agent가 검색 또는 도구 루프로 전문 Agent 결과를 조합한다. 담당자는 근거를 검토하고 체크한 지원자를 직접 결정한다.

**전형과 채용 마무리**: 담당자가 결과 인원을 확인하고 전형 결과를 확정한다. 안내 초안을 검토하고 발송한 뒤 전형을 종료한다. 합격자에게 다음 전형을 반복한다. 마지막 전형의 합격자를 최종 합격자로 정하고 최종 안내 후 채용을 종료하면 리포트를 생성한다.

#### 15 1 상태 구분

| 구분 | 상태와 의미 |
|---|---|
| 채용 진행 | 작성 중 → 공고 게시 중 → 전형 진행 중 → 종료 |
| 전형 진행 | 대기 → 진행 → 결과 확정 → 안내 → 종료 |
| 담당자 결정 | 미결정, 합격, 불합격을 전형별로 관리 |
| 탐색 작업 | AI 선택과 직접 추가는 선택 영역의 구성 정보 |
| 체크 상태 | 합격 또는 불합격 버튼이 적용될 대상 |

상태명은 구현 시 조정할 수 있으나 탐색과 결정의 분리는 유지한다. 전형 결과를 확정하면 미결정자를 불합격으로 포함하고 합격자만 다음 전형 대상이 된다. 다음 전형의 실제 시작은 현재 전형 안내와 종료 이후다. 마지막 전형 확정으로 최종 합격자가 정해지고 최종 안내 후 채용이 종료된다.

### 16 MVP 범위 및 단계

한 달 MVP의 권장 구현 순서다. 주차 구분은 개발 계획을 위한 제안이며 팀별 담당자와 실제 일정은 별도 합의한다. 외부 업체 연동을 늘리기보다 핵심 흐름을 먼저 연결한다.

| 단계 | 구현 범위 | 확인할 산출물 |
|---|---|---|
| 1주차 채용 준비 | 기업 설정, 공고 양식, AI 수정, 전형 구성, 게시, 지원서 | 기업별 절차가 반영된 공고와 실제 지원 접수 |
| 2주차 탐색과 결정 | 프로필 분석, 서류 점수, 공통 화면, Root Agent, 검색, 선택 편집, 담당자 결정 | 조건 요청 → 후보 표시 → 직접 검토와 결정 |
| 3주차 평가와 면접 | 결과표와 제출물 등록, 교차 분석, 맞춤 질문, 답변 기록 | 이전 전형 자료가 다음 전형 분석에 활용됨 |
| 4주차 채용 마무리 | 결과 확정, 안내 수정과 발송, 종료, 리포트, 통합 검증 | 공고부터 최종 리포트까지 E2E 시연 |

### 17 수용 기준

#### 17 1 준비와 지원 접수

- **AC-01 / FR-01~03** 기업 설정을 등록하면 새 공고에 회사 소개, 복지와 필수 문구가 반영된다. AI 수정안은 담당자가 적용하기 전까지 확정 본문을 바꾸지 않는다.
- **AC-02 / FR-04** 서류, 평가, 면접의 반복 및 생략이 가능하다. 전형 이름을 유지하고 모호한 유형은 재질문한다.
- **AC-03 / FR-05** 담당자가 접수 기간과 요약을 확인해 게시하면 자체 채용 페이지가 제공된다. 기간 종료 후 첫 전형이 시작된다.
- **AC-04 / FR-06~08** 필수 정보, 동의 또는 추가 필수 서류가 없으면 제출을 차단한다. 제출한 자료의 분석 결과가 해당 채용의 지원자 프로필에 저장된다.

<!-- PAGE -->

#### 17 2 탐색과 직접 결정

- **AC-05 / FR-10~12** 세 전형 유형에서 공통 화면을 사용하며 자료 Viewer만 유형에 맞게 달라진다. @멘션을 넣고 해제할 수 있다.
- **AC-06 / FR-13~14** 조건 탐색 결과가 리스트, 선택 영역과 Chat 요약에 함께 반영되고 지원자별 근거와 출처를 확인할 수 있다.
- **AC-07 / FR-15** 새 탐색은 기존 결과를 교체하고 이전 선택으로 복구할 수 있다. 추가 요청은 기존 후보를 유지하며 좁히기 요청은 현재 후보 안에서 처리된다.
- **AC-08 / FR-16~17** 넣기와 빼기는 채용 결과를 바꾸지 않는다. 특정 지원자 분석과 비교만 요청하면 선택 영역을 바꾸지 않는다. 서류와 평가 결과를 함께 묻는 요청은 두 자료의 근거를 모두 확인한다. 모호한 편집 대상은 실행하지 않고 재질문한다.
- **AC-09 / FR-19~20** 서류 점수순으로 전원을 표시한다. 미달자는 AI 탐색에서 제외되지만 담당자가 ↑로 검토 가능 영역에 올릴 수 있다. ↑는 선택 추가 및 합격 처리를 수행하지 않는다.
- **AC-10 / FR-21** AI 선택은 테두리, 담당자 결정은 배경색, 서류 기준은 굵기와 회색으로 구분한다. 선택 영역에서 빠지면 AI 테두리를 제거한다.
- **AC-11 / FR-22** 체크가 없으면 결정 버튼이 비활성화된다. 전체 선택을 포함하여 체크한 지원자에게만 합격 또는 불합격이 적용된다.
- **AC-12 / FR-23** 개별 결정은 확인 창 없이 반영되고 직후 되돌릴 수 있다. 결정자는 선택 영역에서 빠지되 전체 리스트에는 남고 복구하면 선택 영역으로 돌아온다.
- **AC-13 / FR-24** 결과 확정 전에 최종 인원과 미결정 포함 인원을 표시한다. 확정하면 합격자만 다음 대상이 되며 미결정자는 불합격에 포함된다.

#### 17 3 평가와 면접 및 마무리

- **AC-14 / FR-25~26** 평가 결과를 이메일 또는 지원번호로 대상자에게 연결하고 결과표 열을 전형 항목에 매핑할 수 있다. 해당 전형의 결과가 프로필에 반영된다.
- **AC-15 / FR-27~28** 이전 전형의 근거로 맞춤 질문을 생성하고 질문별 답변과 직접 추가한 질문을 저장한다. 다음 면접에서 이전 질문과 답변을 확인할 수 있다.
- **AC-16 / FR-29** 안내 초안은 확정 결과와 기업 양식을 반영한다. AI 수정이 필수 문구를 바꾸지 않으며 담당자 발송 전 실제 전송이 일어나지 않는다.
- **AC-17 / FR-30~31** 결과 확정, 안내와 종료를 순서대로 진행한다. 마지막 합격자가 최종 합격자가 되고 채용 종료 후 인원과 근거가 포함된 리포트를 생성한다.

<!-- PAGE -->

#### 17 4 품질과 실행 경계

아래 기준은 기능 구현 이후의 통합 검증에 적용한다. 수치가 제시된 기준은 제품 통제를 확인하기 위한 검증 조건이며 현재 측정 성과를 뜻하지 않는다.

- **AC-18 / NFR-01** 다른 기업이나 권한 없는 채용의 지원 자료를 일반 조회, 검색, Chat 또는 명령 실행으로 가져올 수 없다.
- **AC-19 / FR-22~24, NFR-04** 탐색 요청이나 AI 명령만으로 합격, 불합격 및 전형 확정이 실행되지 않는다.
- **AC-20 / NFR-03** 근거가 없는 정보는 미확인으로 구분하고, 아직 존재하지 않는 전형 결과를 사실처럼 응답하지 않는다.
- **AC-21 / NFR-04~06** 결과 확정 인원, 다음 전형 대상 및 리포트 인원이 일치한다. 반복 요청과 재시도로 결정이나 발송이 중복 적용되지 않는다.
- **AC-22 / NFR-05, NFR-07~08** 분석이나 발송 실패 시 상태를 확인하고 재시도할 수 있다. 실패 전 자료와 담당자의 결정은 보존된다.
- **AC-23 / 8절** 합의된 차별 조건의 탐색 요청을 차단한다. 제출 문서 안의 지시가 도구 권한과 채용 상태를 변경하지 못한다. 도구 루프는 조회 범위와 호출 상한을 지킨다.

### 19 주요 위험 및 대응

| 위험 | 대응과 확인 사항 |
|---|---|
| 서류 점수에 따른 검토 편향 | 미달자를 자동 탈락시키지 않고 전체 자료와 ↑ 검토 경로를 제공한다. 점수 방식과 기준은 사전 확정한다. |
| 근거 없는 분석과 과도한 추론 | 프로필 항목의 원문 근거와 출처를 보존하고 후보의 근거를 재확인한다. 확인된 사실과 해석 및 미확인 내용을 구분한다. |
| 전형 간 잘못된 비교 | 평가 지표의 의미와 결과 매핑을 확인하고 차이가 있다는 이유만으로 부적합 판정을 내리지 않는다. |
| 평가 결과의 대상 연결 오류 | 이메일 또는 지원번호 매핑을 검증한다. 식별되지 않거나 중복되는 자료는 임의 연결하지 않고 확인하도록 처리한다. |
| 탐색과 실제 결정의 혼동 | 테두리, 배경색과 체크 상태의 역할을 구분하고 결과 변경 API를 담당자의 버튼 조작에 한정한다. |
| 미결정자의 의도치 않은 확정 | 확정 전에 미결정 인원과 포함될 불합격 인원을 보여 준다. 확정 취소 범위는 별도 정책으로 결정한다. |
| 개인정보 및 부적절한 탐색 | 기업 및 전형별 접근 통제, 보관과 삭제 정책, 차별 조건 차단 목록과 AI 활용 고지의 검토를 수행한다. |
| 문서의 악성 지시와 과도한 실행 | 원문을 데이터로 취급하고 도구와 서버의 권한 검증을 적용한다. 도구 루프에 호출 상한을 두고 AI에 독자적인 결과 변경 권한을 주지 않는다. |
| 발송 장애와 중복 발송 | 발송 현황을 보존하고 대상별 실패를 확인한다. 반복 요청의 중복 방지와 재시도 정책을 검증한다. |

### 20 완료 정의

MVP는 기업 설정과 공고 작성, 선택한 전형의 진행, 지원자 탐색과 근거 확인, 담당자 결정, 안내 발송, 최종 리포트가 실제로 연결되어 동작할 때 완료된 것으로 본다. 화면만 연결된 시연이나 고정된 AI 응답만으로 완료를 판단하지 않는다.

- Must 기능의 구현과 대응하는 수용 기준 검증을 완료한다.
- 서류, 평가, 면접을 포함한 흐름과 전형의 생략 또는 반복을 검증한다.
- AI 선택과 실제 채용 결과의 분리를 확인하고 담당자의 결정 및 확정 절차를 검증한다.
- 실패, 재시도, 반복 요청과 결과 인원 정합성을 확인한다.
- 구현에 영향을 주는 확정 필요 정책을 합의하고 결과를 문서에 반영한다.
- 남은 제한과 제외 범위를 명시하고 공고부터 리포트까지 시연 가능한 상태로 전달한다.

### 부록 확정이 필요한 정책

아래 항목은 제품 기획과 화면 설계에서 추가 결정이 필요한 정책이다. 표의 권장 확정 시점은 개발 계획을 위한 제안이다. 기능 범위가 확정되어 있어도 세부 정책이 결정된 것으로 간주하지 않는다.

| ID | 항목 | 결정할 내용 | 권장 시점 |
|---|---|---|---|
| OI-01 | 게시 후 전형 변경 | 게시 및 진행 중 추가, 삭제, 순서 변경 허용 범위 | 게시 구현 전 |
| OI-02 | 서류 점수와 기준 | 산정 항목, 가중치, 기준 설정과 변경 방식 | 탐색 구현 전 |
| OI-03 | NCS 평가 영역 | 5개 영역 구성과 직무별 차이 적용 여부 | 평가 구현 전 |
| OI-04 | 결과 확정 취소 | 허용 시점, 권한, 다음 전형과 안내에 미치는 영향 | 확정 구현 전 |
| OI-05 | 선택과 대화 유지 | 페이지 이동 후 선택 상태 유지, 대화 보관 범위 | Chat 구현 전 |
| OI-06 | AI 표시 디자인 | 테두리 색, 강조 효과와 표시 유지 규칙의 상세안 | UI 마무리 전 |
| OI-07 | AI 활용 고지 | 분석 안내 문구, 동의 방식과 법무 검토 | 지원 공개 전 |
| OI-08 | 면접관 권한 | 계정 구분, 자료 열람과 답변 기록 범위 | 면접 구현 전 |

추가 기술 결정으로 인증 방식, Agent 실행 기반, MCP 도입 여부, API 스키마, 서류 분석의 오류 처리, 수치 성능 목표를 확정한다. 기술 구성은 본 제품의 범위와 운영 조건에 맞춰 결정한다.

문서의 기능 기준은 제품 기획서와 화면 설계 스토리보드를 따른다. 기획 담당자와 개발 담당자는 변경 사항을 요구사항 ID, 수용 기준과 관련 정책에 함께 반영한다.
